User mapping is by tenant-bound immutable object ID, never by an unverified email.
Verify that Nikhil's existing ERP roles and IP policies allow the action. After
registration and admin consent, set `enabled: true`, keeping `send_on_request:
false`, and send one agreed test card using bench console:

```python
from snrg_credit_control.outlook_approvals import send_pilot_card
send_pilot_card("Purchase Order", "AGREED_PENDING_PO", "nikhil@snrgindia.com")
```

Test in the approver's supported Outlook client. The human approves the agreed
order directly in email. Check the document, workflow history, requester email,
and in-app confirmation. Repeat for an agreed credit request. Verify an altered,
expired, replayed, or forwarded request cannot apply an approval. Do not approve
real documents just to test. The automated local tests do not replace these checks.

The request signature expires after 24 hours and binds user, doctype, document and
modified timestamp. Any later save requires a new card. Standard PO workflow roles,
conditions and self-approval restrictions still apply. Credit approval calls the
existing app method with its permission checks, amount cap and 7-day policy. Only
POST requests are accepted; normal links and mail scanners cannot approve.

After successful tests, enable `send_on_request` for the mapped pilot users.
Existing request emails remain unchanged, so pilot users may receive both a normal
email and a card. Consolidate the native request notification only after live
verification. No approval-to-requester rules are disabled by this integration.
No historical requests are emailed automatically on installation.

## Rollback

Set `outlook_approvals.enabled` to false. The endpoint rejects actions and existing
ERP approval screens and notification rules continue to work. Roll back the app
release if necessary. Review/revoke the Microsoft Actions preauthorization when
retiring the integration. Do not remove site encryption keys.
